# Kế hoạch hoàn thiện luồng xác minh NFC (FR-04)

> **Lưu trữ.** Tài liệu lịch sử, không cập nhật nữa và có thể đã khác code hiện tại. Hiện trạng: [docs/services/identity/classes/NfcServiceImpl.md](../services/identity/classes/NfcServiceImpl.md).

Ngày lập: 2026-10-19. Đầu vào: [nfc-survey.md](2026-10-19-nfc-survey.md) (mã vấn đề A*, W*, M* lấy từ đó).

## Mục tiêu

Một người dùng đăng nhập web, tạo QR, dùng app Moonkage Verify (cùng tài khoản) quét QR và chạm thẻ; web tự chuyển sang "đã xác minh" mà không cần reload. Chạy với **backend thật**, không chỉ mock server.

## Nguyên tắc

- Không hardcode: URL, chu kỳ, thời hạn đi vào `application.yml` / `../../.env` / `env/*.json`; chuỗi hiển thị vào `messages.properties` hoặc `Strings`.
- Backend kiểm bằng `./mvnw clean verify` (có checkstyle), mobile bằng `dart format . && flutter analyze && flutter test`, web bằng `npm run lint && npm run build`.
- Mỗi giai đoạn kết thúc bằng một lần chạy end-to-end thật, có ghi kết quả.

## Giai đoạn 3 — Đẩy kết quả về web qua WebSocket (AC-04.5)

Hiện trạng: identity đã ghi event `account.nfc_*` vào outbox; orchestrator-service **chưa có WebSocket** (`StompRealtimePublisher` chỉ ghi log, pom chưa có `spring-boot-starter-websocket`) và chưa bind `account.#`.

| # | Phía | Việc |
| --- | --- | --- |
| 3.1 | notification | Thêm `spring-boot-starter-websocket`, cấu hình STOMP endpoint `/ws`, simple broker, user destination `/user/queue/nfc` |
| 3.2 | notification | Xác thực lúc CONNECT: đọc JWT trong header STOMP `Authorization` (dùng chung `JWT_SECRET`), đặt `Principal = accountId` |
| 3.3 | gateway | Route WebSocket `/ws/**` → `lb:ws://orchestrator-service` (theo Software Design mục 9: "WebSocket đi qua gateway ở `/ws`"); kiểm CORS cho origin web |
| 3.4 | notification | Queue `orchestrator.nfc` bind `account.nfc_*` trên `moonkage.events`, consumer đẩy `{type, sessionId, reasonCode, idNumberMasked, lockedUntil}` tới `/user/{accountId}/queue/nfc`. Ghi audit cho `nfc_failed` / `nfc_locked` (NFR-07) |
| 3.5 | notification | Thay stub `StompRealtimePublisher` bằng `SimpMessagingTemplate.convertAndSendToUser` |
| 3.6 | web | `@stomp/stompjs`: subscribe `/user/queue/nfc`, lọc theo `sessionId` đang hiển thị. VERIFIED → thành công; FAILED → hiện lý do và số lần còn lại; LOCKED → hiện thời gian khóa. **Giữ poll** làm dự phòng nhưng giãn chu kỳ (ví dụ 10 giây) khi socket đang nối | 
| 3.7 | test | notification: test consumer + test CONNECT bị từ chối khi thiếu/sai JWT. web: test hook nhận message |

**Xong khi:** tắt poll, web vẫn chuyển trạng thái trong vòng 1–2 giây sau khi app gửi thẻ; thẻ sai cũng hiện lý do ngay trên web (giải quyết W3, W4, A1).

> Nếu tiến độ gấp, giai đoạn này có thể lùi: poll 2 giây đã đáp ứng NFR-10 (< 1 phút). Đổi lại web không biết lần gửi bị từ chối (W4). Có thể vá W4 tạm thời bằng cách cho `GET /api/nfc/sessions/{id}` trả thêm `lastReasonCode`, `attemptsLeft`.

### Kết quả (2026-10-19)

- identity: event `account.nfc_failed` / `nfc_locked` thêm `attemptsLeft` (web hiện "còn N lần").
- orchestrator-service:
  - `spring-boot-starter-websocket` + `nimbus-jose-jwt` 9.37.4. STOMP endpoint `/ws`, simple broker `/queue`, user prefix `/user`. Origin của handshake chỉ nhận `CORS_ORIGINS`.
  - `StompAuthInterceptor`: CONNECT phải có `Authorization: Bearer <access token>` (HS256 `JWT_SECRET`, chưa hết hạn, `type = ACCESS`), STOMP user = account id; SUBSCRIBE chỉ `/user/queue/**`; SEND bị từ chối.
  - Queue bền `orchestrator.nfc` bind 3 routing key; `NfcVerificationEventHandler` ghi `audit_logs` (`NFC_VERIFIED/FAILED/LOCKED`) rồi đẩy `{type, sessionId, reasonCode, attemptsLeft, lockedUntil, occurredAt}` tới `/user/queue/nfc` (không có số CCCD, kể cả đã che).
  - `StompRealtimePublisher` gửi thật qua `SimpMessagingTemplate` (thông báo in-app cũng đi `/user/queue/notifications`).
- gateway: route `orchestrator-websocket` (`/ws/**` → `lb:ws://orchestrator-service`), `permitAll` cho `/ws/**` vì token đi trong frame CONNECT.
- web: `@stomp/stompjs` 7.3.0, `RealtimeProvider` (một kết nối mỗi phiên đăng nhập, tự nối lại, đăng ký lại listener). `useNfcSession` nghe `/user/queue/nfc` theo `sessionId`: VERIFIED → xong (chỉ báo một lần dù poll cũng thấy), FAILED → hiện lý do + số lần còn, LOCKED → thẻ tạm khóa có giờ mở. Poll giữ làm dự phòng: 2 s khi mất kết nối, 15 s khi đang nối (`VITE_NFC_POLL_INTERVAL_CONNECTED_MS`).
- Test: identity 163, notification 23 (thêm verifier, interceptor, handler), gateway 6, web 15. Tất cả `verify` / lint / build qua.
- E2E thật qua gateway với poll khi nối đặt 10 phút: 16/16. Origin lạ bị chặn ở handshake; CONNECT không token / token giả / refresh token nhận ERROR; subscribe hàng đợi người khác nhận ERROR; thẻ hết hạn hiện lý do trên web sau ~0,8 s; thẻ đúng chuyển sang đã xác minh sau ~1,3 s (phần lớn là chu kỳ outbox 2 s). Audit ghi đủ.
- Giới hạn: orchestrator-service không kiểm `password_changed_at` như identity, nên token cũ trước khi đổi mật khẩu vẫn mở được socket tới khi hết hạn (chỉ nhận push của chính tài khoản đó). Broker trong bộ nhớ: chạy nhiều instance notification thì cần broker relay (RabbitMQ STOMP).
